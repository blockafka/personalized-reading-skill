# 增量 Merge Prompt（阅读偏好版）

## 任务

你将收到：
1. 现有的 `reading_habit.md` 内容
2. 现有的 `persona.md` 内容
3. 最近 N 条强信号行为记录（文章标题 + tags + 行为类型）

你的任务是判断行为信号应该更新哪个部分，并输出增量更新内容。

**原则：只追加增量，不覆盖已有结论。如有冲突，输出冲突提示让用户决定。只提取与内容消费相关的信号，忽略纯工作协作内容。不要推断，有依据才写。**

---

## Step 1：分类判断

将行为信号中的每条信息归类：

| 信息类型 | 归入 |
|---------|------|
| 关注领域变化（新主题出现、旧主题衰减） | → reading_habit.md |
| 数据源偏好（频繁点击某来源、屏蔽某来源） | → reading_habit.md |
| 阅读深度偏好（偏好长文/短文、入门/专业） | → reading_habit.md |
| 新鲜度偏好（偏好最新/常青内容） | → reading_habit.md |
| 热度偏好（偏好热门/小众内容） | → reading_habit.md |
| 主动关注/屏蔽关键词 | → reading_habit.md |
| 用户理由中的偏好表达（如"喜欢深度分析"） | → reading_habit.md、persona.md |
| 推荐理由偏好（简洁/详细、论点/摘要） | → persona.md |
| 表达风格偏好（对内容的评价方式） | → persona.md |
| 对热门和争议内容的态度变化 | → persona.md |

---

## Step 2：检查冲突

对比行为信号与现有内容：

- 如果信号**补充**了现有信息（新主题、新关键词）→ 直接追加
- 如果信号**确认**了现有信息 → 忽略（不重复写）
- 如果信号**与现有信息矛盾**（如之前屏蔽某主题，现在频繁点击）→ 输出冲突提示：

```
⚠️ 发现冲突：
- 现有：{现有描述}
- 新信号：{行为描述}
- 来源：{行为类型 + 文章标题}

建议：[保留现有 / 更新为新内容 / 两者都保留并标注时间]
请用户决定。
```

---

## Step 3：生成更新 Patch

对 `reading_habit.md` 的更新，输出格式：
```
=== reading_habit.md 更新 ===

[追加到"核心关注领域/{主题}"节]
- {子主题}（权重：高，来源：{N} 次 save/like）

[追加到"主动关注关键词/{类别}"节]
- {关键词}

[追加到"屏蔽关键词"节]
- {关键词}（原因：用户点击"不感兴趣"）

[追加到"更新记录"节]
- {日期}：{更新原因摘要}

[无更新] 或 [以上章节有更新]
```

对 `persona.md` 的更新，输出格式：
```
=== persona.md 更新 ===

[追加到"互动偏好/推荐理由格式"节]
- {新偏好描述}

[追加到"对'热门'和'争议'标签的态度"节]
- {新态度描述}

[追加到"更新记录"节]
- {日期}：{更新原因摘要}

[无更新] 或 [以上章节有更新]
```

---

## Step 4：生成更新摘要

向用户展示：
```
本次更新摘要：
- reading_habit.md：追加了 {N} 条新信息（{简要描述}）
- persona.md：追加了 {N} 条新信息（{简要描述}）
- 发现 {N} 处冲突，需要你确认（见上方）

版本将从 {vN} 升级到 {vN+1}。
确认应用更新？
```
